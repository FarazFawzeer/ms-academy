# MS Football Academy – project handoff

Management system for **MS Football Academy** (Sri Lanka). Freelance project for Faraz. Built on his existing Laravel admin theme (Taplox-based). Live target: **msfootballacademy.com** on Spaceship shared hosting (cPanel).

Rule from the owner: always give **complete replacement files**, not diffs. Non-technical staff use it, so keep the UI simple, clean and mobile friendly.

## Stack
Laravel 11/12, PHP 8.2+, Blade, Bootstrap 5, iconify-icon (solar set), ApexCharts, SweetAlert (Swal), html5-qrcode (camera needs HTTPS), bacon/bacon-qr-code, maatwebsite/excel, GD for images. Assets built with `npm run build` locally, then `public/build` is uploaded.

Timezone is **Asia/Colombo** (`config/app.php` default and `APP_TIMEZONE` in `.env`). Scan times, payment times and "today" (attendance date, undo, coach workdays) all depend on it.

## Business rules
- **Fee plans by training days** (`config/academy.php` `plans`, `Player::plan()` / `planFor()`): Friday & Sunday LKR 3,500 for 8 sessions; Friday only or Sunday only LKR 2,500 for 4. The payment popup fills in the player's plan (`openPayment(id, name, plan)`).
- **Every practice on the player's training days uses a session, present or absent** (client, 24 Oct 2026). Present: −1 at scan time. Absent: −1 when the day is settled (see below). Once the package is used up (balance ≤ 0) absences cost nothing (`absences.counted = 0`); attending without paying still goes negative = payment due. An Admin "extra day" override also uses a session.
- `players.sessions_balance` = paid sessions − attended − counted absences − sessions entered as "already used" when the player was added.
- Reminder fires when the balance drops to exactly one week of practice (`Player::remindThreshold()` = number of training days: 2 for Fri+Sun, 1 for one day), sets `reminder_pending`. A payment clears it.
- **Extra days** (Admin only, profile > Give Extra Days, `PaymentController@extraDays`): free sessions with a reason, saved as a LKR 0 payment with method `extra` (shows as "Extra days" / "Free").
- **Adding a player who paid before the system** (`PlayerController@store`, `payment_mode` = `now` | `before` | `none`): `before` saves the plan payment on "Paid on" (optional, default today), takes off "Sessions already done", and turns each optional session date into an attendance row (`recordEarlierPackage()`).
- One attendance per player per day (UNIQUE `player_id, attendance_date`). Undo is allowed for today only and gives the session back.
- Coach pay = daily wage. A workday snapshots the rate; paid days are locked.
- Player IDs use `config('academy.player_prefix', 'MS')`, e.g. MS-0012.
- Roles in `users.type`: Super Admin, Admin, Front Desk (`UserController::TYPES`). Front Desk can scan, add players, take payments, see reminders, the register and age groups. Admin-only (via `EnsureUserType:Super Admin,Admin`): payment delete, practice schedule, coaches, workdays, salary, reports, users.

## Age groups, training days, practice schedule (client change, Oct 2026)
Replaced manual batches (table, model, controller, page all removed).
- **Age group is never stored on the player.** `App\Support\AgeGroup` works it out from `dob` and today's date, so a player moves up on their birthday. Bands in `config/academy.php` `age_groups` (name => highest age): U8 ≤7, U10 8-9, U12 10-11, U14 12-13, U16 14-15, U18 16-17, then `senior_group` (Senior). `Player::scopeInAgeGroup()` turns a group into a DOB range for SQL. `attendances.age_group` keeps the group *on that day* for reports.
- **Training days**: `players.training_days` = `fri`, `sun` or `fri,sun` (keys of `config('academy.training_days')`, which also holds the default times, currently 4:00-5:30 PM for both; Sunday time not confirmed by the client). Player form has Friday/Sunday toggles, at least one required.
- **Practice schedule** (`practice_sessions`, `PracticeSession` model, one schedule for the whole academy): regular Fri/Sun sessions are created on demand by `PracticeSession::generate($from, $to)` (INSERT OR IGNORE on `slot, planned_date`, never before `schedule_start`). `fillAround()` covers ~5 weeks back to `schedule_weeks_ahead` (8) ahead; `forDate($d)` returns the non-cancelled session on a day. Admin can move a session (`session_date` != `planned_date`), change time/note, cancel/restore, or add an extra one for Friday or Sunday players. One active practice per date. A session with attendance is locked (no move/cancel). Moved/cancelled sessions are never re-created.
- Do not name static model methods `fill()` or `on()` (Eloquent already has them). Dates on `PracticeSession` are stored as plain `Y-m-d` via mutators because exact-date lookups depend on it.
- **Attendance rule** (`AttendanceController@mark`): allowed only when today has a practice AND the player trains on that slot. Otherwise 422 `no_practice` / `wrong_day`. An Admin gets `can_override` and can resend with `force=1`; the row is saved with `is_extra = 1`. Front Desk cannot override. Session counting (−1 per attendance) is unchanged; absences cost nothing.
- **Register** (`attendance/register`, replaces History): month grid of players × practice days grouped by age group, like the client's old Excel. Cells: present, AB (expected, not marked), extra (blue), not their day (·), cancelled (hatched), future (blank). Columns for moved (MOVED), cancelled (OFF) and extra days (EXTRA). Attended/expected and rate per player, present count per day, Excel export with the same grid.
- **Print ID Cards** (`players/print`, sidebar Players > Print ID Cards): pick All players, Age group, ID range (MS-0010 to MS-0025, reversed or "MS-" prefixed input accepted) or Pick players (search + tick list, select all shown). Optional training-day filter, include-inactive switch, order by name or ID; live card and A4 sheet count. Opens `players/cards` in a new tab with `ids`, `from`/`to`, `group`, `days`, `inactive`, `sort` query params. Single-card buttons on the list and profile still link to `players/cards?ids=N` directly. Player numbers equal the id (zero padded), so the range filters on `id`.
- Dashboard shows today's practice (or the next one); scan page shows a "Today: Sunday practice" / "No practice today" banner; manual search tags players "Not today".
- **Settling finished practice days**: `SettlePracticeDays` middleware (on every logged-in route) calls `PracticeSession::closePending()`. For each finished, not cancelled day without `closed_at` (on or after `schedule_start`) it claims the day (sets `closed_at` first, so it is never settled twice), then writes an `absences` row for every active player who trains that day, had joined and was not marked, and uses a session if they still have one. Today's practice is settled tomorrow. Inactive players are skipped.
- **Register cells** now also show `U` = absent but not counted (grey AB) and `T` = today, not marked yet. Absences come from the `absences` table for settled days.
- **Scanner (built for ~100 players)**: camera scans non-stop (BarcodeDetector when the phone has it, 15 fps, same card ignored for 6 s), big green/amber/red flash over the camera + beep + vibrate, screen kept awake (Wake Lock), restarts by itself after a refresh if it was on (localStorage `ac-scan-on`). Name search: Enter marks when exactly one player matches. Admin "Mark anyway (extra day)" stays in the result card.
- **Date fields**: every `<input type="date">` is upgraded app-wide by `partials/date-picker` (flatpickr 4.6.13 from jsDelivr, base CSS inserted before the theme CSS): type `31/12/2015`, `31-12-2015`, `31122015` or `2015-12-31`, or pick from a calendar with month list + year box. Shown as dd/mm/yyyy, sent as YYYY-MM-DD. `data-picker="dob"` opens about 10 years back. Use `ACDate.set(input, value, {min, max, locked})` and `ACDate.enhance(el)` for fields set or added by JS. Without internet the plain browser date field still works.
- **Row actions**: icon-only buttons were replaced everywhere by labelled buttons (`Pay`, `Edit`, `Send`, `Undo`, `Change`, `Cancel`, `Delete`) plus a `⋮` "More actions" menu with labelled items. Players list: `Pay`, `Edit` (icon only on phones) and `⋮` (View profile, Print ID card, and for Admins Delete player). Shared styles in `partials/app-ui` (loaded in `head-css`): `.ac-actions`, `.ac-more`, `.ac-person`, `.ac-hide-xs`, `.ac-photo-sm-only` (no list photo on phones), phone tweaks. While a `⋮` menu is open its `.table-responsive` gets `overflow: visible` (CSS `:has`) so menus are never cut off. Do NOT use Popper `strategy: fixed`: the theme puts a transform on a parent, so fixed menus were drawn off-screen (client could not see the menu).
- **Delete player** (Admin only, `PlayerController@destroy`, `DELETE admin/players/{id}`): from the players list `⋮` or the profile. Shared confirm `deletePlayer(id, name, done)` in `partials/js-helpers` warns that attendance and payments go too (payments leave the reports) and suggests Deactivate instead. Attendance, payments and absences cascade; the photo file is removed.
- **Sidebar is flat for Players and Coaches** (client: fewer menu items). Players page header has Age Groups, Print ID Cards, Add Player; Age Groups and Print ID Cards have an "All Players" back button. Coaches page header has Daily Attendance, Salary, Add Coach; Daily Attendance and Salary have a "Coaches" back button. Only Attendance (Scan / Mark, Register) still has a submenu.
- **Phones**: at 375 px wide every page fits without sideways scrolling (register grid scrolls on purpose, names pinned); on phones the balance / group / role / rate badges move under the name instead of their own columns.

- `deploy.bat check` (login works + folder has `artisan`, shows whether `.env` exists), `deploy.bat preview` (lists what would upload), `deploy.bat` (asks Y/N, uploads new/changed files with `synchronize remote -criteria=time`, then deletes `bootstrap/cache/*.php` and compiled views on the server = config/route/view clear), `deploy.bat deploy /y` (no question). - The WinSCP script is written to %TEMP% and deleted after each run (it can hold the password); logs go to `deploy\logs\` (git-ignored; WinSCP hides passwords in logs). `.bat` files are kept CRLF via `.gitattributes` (`*.bat text eol=crlf`) - LF line endings break `goto` in cmd.
